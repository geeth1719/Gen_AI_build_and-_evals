1. HNSW: Hierarchical Navigable Small WorldThe Core ConceptImagine skipping through a massive city. To get from one side of the city to a specific house on the other side:You take a highway across state lines (broad jumps).You take a main avenue into the right neighborhood (medium jumps).You walk down local streets until you reach the exact house (tiny jumps).HNSW applies this exact multi-layer concept to high-dimensional vector spaces using a hierarchical graph structure.PlaintextLayer 2 (Highways):      [ Node A ] ───────────────────────────────► [ Node Z ]
                             │                                           │
 Layer 1 (Avenues):       [ Node A ] ──────────► [ Node M ] ───────────► [ Node Z ]
                             │                      │                    │
 Layer 0 (Local Streets): [ Node A ] ─► [ Node F ] ─► [ Node M ] ─► [ Node P ] ─► [ Node Z ]
How It Works Under the HoodMulti-Layer Graph Construction:Layer 0 (Bottom): Contains every single vector in your database, connected to its closest neighbors.

Upper Layers: Contain probabilistic skip-lists (subsets of vectors). Higher layers have fewer nodes and much longer connection spans ("highways").

Search Traversal ($O(\log N)$ Time):The search starts at an entry point in the top layer.It evaluates neighbor vectors and greedily jumps to the neighbor closest to the query vector until it hits a local minimum (it can't get any closer on this layer).It drops down one layer at that exact node position and repeats the greedy search with smaller, finer steps.

It continues dropping layers until it reaches Layer 0, where it fine-tunes the search to return the top-$K$ nearest vectors.

Why HNSW Dominates Vector DatabasesSpeed: Logarithmic time complexity ($O(\log N)$) makes it blazingly fast.

Accuracy: Yields high recall (>95-98%).Trade-off: High RAM usage. Because it builds and stores explicit multi-layer graph edge lists in memory, HNSW requires significant RAM.

2. IVF-PQ: Inverted File with Product QuantizationWhere 

HNSW prioritizes speed, 

IVF-PQ prioritizes RAM efficiency and scalability. 

It combines two separate compression techniques: Inverted File Indexing (IVF) and Product Quantization (PQ).

Part A: Inverted File Index (IVF) — "Don't Search the Whole Room"Instead of searching all $N$ vectors, IVF partitions the vector space into $K$ distinct clusters (called Voronoi cells) using $K$-Means clustering.


***************************************************************************************************************************************************************************************************************

Part B: Product Quantization (PQ) — 
"Compress High Dimensions to Tiny Byte Codes"Even within a cluster, holding 1,536 floating-point numbers ($1,536 \times 4 \text{ bytes} = 6.1 \text{ KB per vector}$) eats gigabytes of RAM. PQ drastically compresses vectors using lossy compression:Splitting: A 1,536-dimensional vector is sliced into $M$ smaller sub-vectors (e.g., 8 sub-vectors of 192 dimensions each).Quantization: Each sub-vector is assigned to its nearest codebook centroid and replaced by an 8-bit integer ID (0 to 255).Compression Result: Instead of storing 6,144 bytes per vector, you only store 8 bytes (an array of 8 codebook IDs)! This represents a 95%+ reduction in RAM usage.
